# VAT V01-V08: API web `/api/web/vat/` (G1 v1) para INET React

Contrato ejecutable (#2785, #2794), 2026-11-10. Fuente: `HEAD` 652dc77f2 (merge de
`origin/development` 83d87cd41). Regla G1 v1:
`docs/registro/decisiones/2026-11-06-2808-protocolo-g1-v1.md`. Cambio que muda la API:
`docs/registro/cambios/2026-T4/2026-11-10-2794-api-web-vat.md`.

## Dueño, runtime y convenciones

- Dueño: vertical `vat` (`src/backends/config/backends.json`, runtime `vat_runtime.urls`).
- Prefijo publicado: `api/web/vat/` en `url_prefixes` de `vat`. **No queda `api/inet/`**:
  ni prefijo en el proxy, ni ruta en el runtime, ni alias sin compuerta.
- URLs: `src/backends/vat/VAT/web_api_urls.py` (namespace `vat_web_api`), montado en
  `src/backends/vat/vat_runtime/urls.py`. El monolito lo recibe por `config.urls_all`, que
  antepone los `backend_urlpatterns` de cada backend al `api/web/` del core.
- Vistas: las de INET (`src/backends/vat/VAT/api_inet_views.py`). La base `InetAPIView` usa
  `InetSessionAuthentication` y `permission_classes = [WebGatePermission, IsAuthenticated]`;
  después cada vista aplica `check_read`, `check_write`/`can_mutate` y el alcance por CFP.
- Escritores únicos: ModelForms de `VAT.forms` y services `VAT.services.inet_workflow`,
  `inet_forms` e `inet_queries`, compartidos con las vistas legacy
  (`views/centro.py` usa `crear_centro`/`actualizar_centro`, `views/comision_curso_wizard.py`
  usa `crear_comision`, `views/curso.py` usa `guardar_asistencia`).
- Contrato OpenAPI: `src/frontends/packages/api/openapi.inet.yaml`, generado con
  `config.urls_inet_v2` (ahora monta `api/web/vat/`). `operationId` sin cambios
  (`inet_<recurso>_<método>`: `InetSchema.MOUNT_PARTS = 3`). Tipos:
  `src/frontends/packages/api/src/inet.generated.ts` (`npm run inet:types`).
- Cliente: `inetClient = crearCliente("/api/web/vat/")` en
  `src/frontends/packages/api/src/inet.ts`; proxy de Vite `"/api/web/vat"`.
- Respuestas: JSON; G1 agrega `Cache-Control: private, no-store` y `Vary: Cookie`. Sin
  reintento automático; en POST/PUT/DELETE un 504 trae `uncertain: true` (proxy del core).

## Permisos (iguales a `/api/inet/`, más G1)

1. Core (proxy): sin sesión 401 JSON; requisito web pendiente (`web_access_denied`,
   `password_change_required`, `profile_confirmation_required`,
   `mandatory_survey_required`) 403 JSON con `state` y `required_action_url`; no reenvía.
2. Runtime VAT: `WebGateMiddleware` verifica la constancia (401/403/503 JSON sin negocio).
3. Vista: `WebGatePermission` (en el monolito evalúa la política local e ignora el header),
   `IsAuthenticated`, CSRF de `SessionAuthentication` en métodos no seguros.
4. Acción: `VAT.view_<codename>` para leer; `add/change/delete_<codename>` para escribir
   (`can_mutate`); `planes` además exige SSE o provincial (`is_vat_sse`,
   `is_vat_provincial`).
5. Objeto: `resource_queryset` limita por CFP/provincia del actor; un padre ajeno da 404.
   `can_user_edit_centro` decide la edición del CFP.

Cambio de comportamiento: quien tiene un requisito web pendiente ya no usa INET hasta
completarlo (antes `/api/inet/` no lo evaluaba). El cliente compartido convierte el 403 en
`SinPermiso` con el `detail` del back; INET muestra ese mensaje y no redirige a
`required_action_url` (ver Riesgos).

### Campo por campo (V02-V07)

Los campos de cada formulario salen del ModelForm nativo (`InetFormView` serializa
`FORM_CLASSES[recurso]`, `inet_forms.serialize_form`), así que nombre, obligatoriedad,
opciones y validación son las del form legacy. Diferencias deliberadas, ya cubiertas por
`test_inet_api.py`:

- `centros`: conserva identificador y sede principal; `activo_present` del form legacy.
- `cursos`: la modalidad la fija el plan (`test_course_reuses_plan_and_modality_validation`).
- `comisiones`: ubicación y horarios se validan juntos y atómicamente; la edición conserva
  horarios históricos y asistencia.
- `planes`: provincia obligatoria en alta manual y conservada en edición.
- Opcionales aceptan `null`; `ModelMultipleChoiceField` se describe como multiselect.

Los listados usan `DETAIL_FIELDS`/`serialize_item` (`inet_queries.py`), un subconjunto del
detalle legacy. La comparación columna por columna contra cada template legacy queda como
criterio de aceptación de la entrega React de cada flujo, no de este traslado.

## Entregas

1. **VAT-API01 (este cambio)**: mudar las 63 rutas a `/api/web/vat/` con G1, sin alias, y
   actualizar todos los consumidores. Sin cambios de React salvo la base del cliente.
2. **VAT-API02**: INET React maneja el 403 de requisito (`state`, `required_action_url`)
   como `InsumosAccessError` en `apps/sisoc`, redirigiendo a la ruta interna segura.
3. **VAT-V01 / VAT-V08**: contratos propios (vouchers, evaluaciones y reportes).
4. **VAT-V02..V07 restos**: las acciones marcadas «sin API» arriba, cada una con su vista
   web sobre el escritor nativo.

## Criterios de aceptación (VAT-API01)

- Ninguna ruta, prefijo, registro, contrato OpenAPI, tipo generado, cliente, mock E2E ni doc
  vigente usa `/api/inet/` (`git grep -n "api/inet"` solo en registros históricos).
- En el runtime de VAT, un request sin constancia o con constancia de otro `aud`/`target`
  responde 403 `{"detail": "Solicitud no autorizada."}` sin ejecutar negocio; sin sesión,
  401 `{"detail": "Inicie sesión para continuar."}`.
- Con constancia válida, `POST /api/web/vat/cursos/` crea el curso con el mismo form nativo;
  sin constancia no crea nada; sin CSRF responde 403 aunque la constancia sea válida.
- En el monolito, un requisito pendiente responde 403 con `state` y `required_action_url`.
- `test_inet_api.py` pasa completo sobre `/api/web/vat/`.
- `openapi.inet.yaml` e `inet.generated.ts` solo cambian en los paths; `--fail-on-warn` pasa.

## Estrictamente humano

Nada bloquea VAT-API01. Decisión recomendada a confirmar por el responsable: aceptar que
INET exija los requisitos web del core (403 hasta completar contraseña, perfil o encuesta
obligatoria), como el resto de las APIs `/api/web/<vertical>/`. Recomendación: **sí**, es
la regla G1 aprobada el 2026-11-06.

## Riesgos

- Despliegue: core y runtime VAT deben salir juntos con el front INET; un front viejo contra
  un back nuevo recibe 404 en `/api/inet/`. Sin alias por pedido explícito.
- Usuarios con requisito pendiente ven el mensaje del 403 en INET y no una redirección
  hasta VAT-API02.
- Los enlaces `next`/`previous` de la paginación se arman con el host que recibe el runtime;
  el cliente usa rutas relativas, así que no los sigue.
- La ventana de 60 s de G1 y el timeout de gunicorn aplican a todas las operaciones INET.
