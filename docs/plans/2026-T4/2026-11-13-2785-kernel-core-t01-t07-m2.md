## Acceso (se conserva exactamente)

- Todas las vistas son `login_required`/`LoginRequiredMixin`. La API web aplica antes la puerta común (`401` sin sesión,
  `403` con requisito web pendiente) y después la regla nativa de cada ruta.
- Programas: solo sesión autenticada. Cualquier usuario autenticado lista, crea, edita y elimina. No se agregan
  permisos: decisión `docs/registro/decisiones/2026-11-10-2785-t05-programas-acceso-actual.md`.
- Papelera: solo superusuario (`SuperAdminRequiredMixin`, `403` para el resto). El `POST` de restauración
  repite la comprobación `is_superuser`.
- Novedades, arquitectura, inicio, geografía y preferencias: cualquier usuario autenticado. Geografía filtra por el
  alcance territorial del usuario (`get_geography_scope_map`), igual que hoy.
- `/api/renaper/consultar/`: solo `HasAPIKey`; una sesión web sin clave no entra y una clave no abre ninguna ruta de sesión.
  No se expone ninguna credencial.

## Datos y reglas

- Novedades: el contenido sale de `CHANGELOG.md` (archivo local; GitHub como respaldo), se parte por cabeceras
  `## Despliegue: AAAA.MM.DD` o `# Versión SISOC DD.MM.AAAA`, se convierte con `markdown` (`extra`, `sane_lists`) y se cachea 24 h
  bajo `changelog_content`. El parseo y el caché siguen en el backend: React recibe HTML ya convertido y no lo vuelve a analizar.
  Un resultado sin versiones no se cachea y produce el estado de error.
- Arquitectura: `var/arquitectura/grafo.json` (fuera de `static/`). La página informa si el grafo está disponible y la hora
  de generación (`dd/mm/AAAA HH:MM`, hora local). El grafo describe estructura interna: nunca se copia a un asset.
- Programas: `Programa(nombre único, estado, observaciones ≤ 500, organismo_id, descripcion)`; listado ordenado por
  nombre, 25 por página; `ProgramaForm` guarda `organismo_id`; `clean()` capitaliza el nombre.
- Papelera: modelos con borrado lógico registrados; filtros `model`, `q`, `deleted_by`, `deleted_from`, `deleted_to`;
  25 por página; la restauración es en cascada (`instance.restore(user, cascade=True)`), no un update directo.

## Acciones y efectos (textos verbatim)

| Acción | Efecto persistido | Mensaje / respuesta |
|---|---|---|
| Crear programa | Alta de `Programa`; redirección al detalle | «Programa creado correctamente.» |
| Editar programa | Actualiza los campos del formulario; redirección al detalle | «Programa actualizado correctamente.» |
| Eliminar programa | Borra el registro (físico) y vuelve al listado | El método `delete()` que escribe «Programa eliminado correctamente.» no se invoca con la `DeleteView` de Django actual: se conserva el comportamiento observado (la prueba lo fija) |
| Rechazo de formulario | Nada se escribe | `400` con el formulario ligado y sus errores |
| Restaurar (sin `confirmed=1`) | Nada | Redirige a la vista previa |
| Restaurar (confirmado) | `restore(cascade=True)` | «Restauración completada. Registros restaurados: N.» |
| Restaurar con `ValidationError` | Nada | Mensaje de error del `ValidationError` y vuelta a la vista previa |
| Guardar columnas / favoritos | Fila `PreferenciaColumnas` / `FiltroFavorito` del usuario | Errores: «Listado invalido.», «Columnas invalidas.», «Seccion invalida.», «El nombre es obligatorio.», «El nombre ya existe.», «Filtros invalidos.», «El filtro contiene parametros obsoletos.», «Filtro favorito no encontrado.» |

Textos de pantalla (verbatim de las plantillas): «No hay programas registrados.», «Confirmar eliminación», «¿Eliminar el programa …?»,
«Esta acción no se puede deshacer. Verificá que el programa no esté en uso antes de eliminarlo.», «Papelera Global»,
«No hay registros eliminados para este modelo.», «Vista previa de restauración», «Restaurar en cascada»,
«No fue posible obtener las novedades del sistema en este momento.», «El mapa de arquitectura todavía no fue generado».

## API web (`/api/web/core/`)

| Método y ruta | Equivale a | Respuesta |
|---|---|---|
| `GET novedades/` | `changelog_view` | `{current_version, versions[{version, html}], error, architecture_url, messages}` |
| `GET arquitectura/` | `mapa_arquitectura_view` | `{grafo_disponible, generado, data_url, back_url}` |
| `GET programas/` (`?page`) | `ProgramaListView` | `{items[{id,nombre,organismo,estado,urls}], pagination, messages}` |
| `GET programas/<pk>/` | `ProgramaDetailView` | detalle del programa y mensajes |
| `GET programas/crear/`, `POST` | `ProgramaCreateView` | formulario / `{ok, redirect}` / `400` con errores |
| `GET programas/<pk>/editar/`, `POST` | `ProgramaUpdateView` | ídem |
| `GET programas/<pk>/eliminar/`, `POST` | `ProgramaDeleteView` | confirmación / `{ok, redirect}` |
| `GET papelera/` (filtros, `?page`) | `TrashListView` | filas, filtros, filtros activos, paginación |
| `GET papelera/restaurar/<app>/<model>/<pk>/` | `TrashRestorePreviewView` | vista previa de cascada |
| `POST papelera/restaurar/<app>/<model>/<pk>/` | `TrashRestoreView` | `{ok, redirect}` |

Cada vista web ejecuta la vista nativa (`setup()`, `get_context_data()`, `post()`), sin reescribir su regla. Los
mensajes en cola se consumen en la página que los muestra, como en la plantilla nativa.

## Módulo React (`apps/sisoc/src/routes/`)

`coreNovedades`, `coreArquitectura`, `coreProgramas` (listado y detalle), `coreProgramaForm`, `coreProgramaBaja`,
`corePapelera`, `corePapeleraRestaurar`; registrados en `routes/index.ts`; reutilizan `MainFrame`, `nativeParity`,
`listControls` (`Pagination`) y el marco `SisocShell`. Ningún control queda inerte: cada botón o enlace ejecuta
la acción nativa o navega a la ruta nativa.

## Criterios de aceptación

1. Mismas rutas, mismo texto, mismos controles y mismo orden de Tab que la plantilla nativa (tolerancia 2 px, diff perceptual ≤ 1 %).
2. Anónimo `401`; sin requisito web `403`; sin permiso (papelera) `403`; `POST` sin CSRF `403`; cabecera de puerta falsificada ignorada.
3. Toda escritura pasa por la vista nativa y tiene prueba de efecto persistido y de «sin cambios» ante rechazo.
4. T04 y T07 no cambian ninguna respuesta: las pruebas de contrato fallan ante cualquier cambio de forma o de mensaje.
