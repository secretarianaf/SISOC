# Autenticación SIIS y habilitaciones independientes

Estado: implementación local pendiente de pruebas Django, revisión e incorporación. No desplegada; no se emitieron credenciales ni se ejecutaron migraciones sobre datos reales.

## Comportamiento

- `/api/users/login/` selecciona SIIS con `app: "siis"` y API key; devuelve únicamente los siete campos de identidad acordados. El login sin `app` conserva el contrato legacy.
- `/api/users/siis/admin-token/` emite el token firmado por una hora; `/api/users/siis/` exige ese token, API key y permiso vigente `auth.add_user`. Alta activa solo para SIIS, sin privilegios ni contraseña temporal visible.
- Se rechazan duplicados normalizados de username, email y DNI con `409`, sin cambiar cuentas existentes. Los DNI admiten 7–8 dígitos, puntos y espacios ASCII; estos separadores se ignoran también en cuentas existentes.
- `Profile.acceso_web` y `Profile.acceso_siis` se administran en el formulario web y Django admin. El formulario aplica las restricciones existentes de la sección Administración de accesos. El flag web no concede staff ni permisos.
- El login web y `/admin/` exigen acceso web; el middleware compartido bloquea también la siguiente solicitud de sesiones abiertas, excepto API, estáticos, media y logout.
- DataCalle puede coexistir con representantes y territoriales; se mantienen las reglas de rol y conflictos territoriales. El guardado usa la delegación de grupos/permisos existente y conserva permisos PWA administrados por sus propios campos, sin vaciar permisos ajenos por ser usuario mobile.

## Migraciones y transición

`users.0060_profile_accesos_siis_web` añade los campos sin dependencias core. `pwa.0026_inicializar_acceso_web` realiza la inicialización histórica en el dueño core, con modelos históricos y alias del migrador: bloquea PWA activo/coordinador configurado y entrevistador DataCalle según la lógica web anterior. Conserva los demás accesos, incluidos coordinadores/administradores DataCalle, Territorial y Ticketera que ya podían entrar. Después no se recalcula por rol.

Las altas automáticas PWA/operator e importaciones PWA fijan acceso web deshabilitado; las altas web muestran el flag marcado por defecto y SIIS siempre lo deshabilita. Las demás altas conservan el acceso anterior mediante el default del modelo.

La inicialización solo es segura como parte de la transición, antes de administrar los flags nuevos. No volver a ejecutar su función sobre cuentas ya administradas: sobrescribe valores. Su reversa no recalcula habilitaciones. El migrador del grafo completo debe aplicar ambos pasos antes de abrir tráfico con el código nuevo.

**Rollback:** volver al código anterior que ignora `acceso_web` puede habilitar web a cuentas solo SIIS. Una reversión debe conservar el gate o requerir una mitigación explícita; no basta con mantener las columnas. No se ejecutó rollback ni deploy.

Límites aceptados: sin garantía adicional de unicidad concurrente DNI/email, sin revocación individual del token, cualquier API key válida, sesiones ordinarias en SIIS, contraseña inicial reutilizable y no bloqueo SIIS por contraseña temporal vencida/cambio pendiente.
