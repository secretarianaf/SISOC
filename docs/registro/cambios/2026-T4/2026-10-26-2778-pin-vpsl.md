# Cambio: pin en Ver para ser libres (#2778, cuarta etapa)

## Alcance

Editor de ubicación en sedes y jornadas, tanto Django como React. Se reutilizan
los modelos, coordenadas, permisos, alcance provincial y guardado existentes.
No agrega migraciones, settings, permisos ni dependencias npm/Python.

`UbicacionVPSLForm` comparte los campos decimales y la validación del par entre los
dos formularios de VPSL. Acepta cero y rechaza coordenadas fuera de rango o pares
incompletos. Formularios anteriores que omiten los campos conservan el flujo
previo: sedes mantienen coordenadas al editar contacto y las limpian si cambió el
domicilio; jornadas siguen resolviendo el enlace de Google Maps.

Cuando se envía un par explícito desde el pin, la sede lo conserva aunque se
edite el domicilio. La jornada prioriza ese par y no sobreescribe el domicilio
con el del enlace. Un enlace nuevo sigue validándose con el resolver seguro
existente; si falta enlace y hay coordenadas válidas se genera la URL canónica.

## Frontend y contrato

- Django reutiliza el componente del kernel. Sedes buscan por domicilio y las
  jornadas conservan Buscar enlace; su resultado actualiza coordenadas y mapa.
- React usa `MapPinEditor.tsx` como adaptador del mismo editor Leaflet, sin otra
  dependencia: entradas internas sin nombres evitan duplicar datos enviados;
  los eventos actualizan el estado y los campos visibles del formulario.
- `pin:init` permite montar el editor al navegar en React; `pin:destroy` libera
  el mapa e invalida búsquedas pendientes al salir. Leaflet se carga con SRI y
  versión fija, como el mapa general de Dispositivos.
- El servicio compartido de búsqueda se activa de forma explícita con Buscar
  dirección incluso si había coordenadas anteriores; descartar restaura el par
  previo. No se geocodifica ni guarda automáticamente al abrir la pantalla.
- Cuando Georef devuelve varias coincidencias, el editor acerca el mapa a una
  referencia aproximada y lo explica. No completa coordenadas hasta que la persona
  mueva el pin o confirme el centro; una coincidencia única conserva el llenado
  directo. Se evita que una búsqueda ambigua deje el mapa a escala nacional.
- OpenAPI y los tipos TS se regeneran para incluir el par opcional. El enlace de
  jornada es condicional a las coordenadas, tanto en navegador como en servidor.
- Vite reenvía `/static/` y `/ajax/ubicacion/` al Django local. Producción sigue
  usando el mismo origen de Django para sesión/CSRF, assets y API.

## Organización del formulario React de sedes

Se agrupan datos de sede, ubicación, contacto e información adicional, siguiendo
el patrón de secciones del registro nominal. Ubicación comienza por domicilio
(calle y altura), luego provincia y localidad; continúa con departamento/códigos
y coordenadas. El mapa queda al final del grupo, después de longitud. Una prueba
verifica el orden y que teléfono y nombre estén en sus respectivas secciones.
Chrome verificó el orden y el ancho móvil sin desborde (390 px). Tests frontend:
15 pasaron; build y ESLint correctos antes del ajuste de ancho del domicilio.
Distribución y búsqueda confirmadas por quien pidió en Sedes React.

## Corrección del entorno local de revisión React

Se reprodujo un rechazo CSRF al buscar desde Vite directo: el script temporal
de revisión usaba `changeOrigin: true`. Se corrigió fuera del repositorio para
conservar Host, siguiendo el valor predeterminado del proxy Vite del proyecto.
No se alteraron las comprobaciones CSRF ni sus orígenes confiables. Se documentó
la diferencia entre revisar por Django y entrar directamente a Vite.

Búsqueda completa desde React verificada tras corregir el proxy temporal: POST
autenticado respondió 200, coincidencia única y campos visibles actualizados.

## Búsqueda por dirección en Jornadas

Verificar ubicación se habilita con dirección y localidad aunque el enlace esté
vacío. En ese caso usa el buscador compartido y la provincia fija del itinerario;
con enlace mantiene su resolución anterior. La API expone esa provincia como
metadato opcional del esquema, sin campos editables ni permisos adicionales.
La plantilla Django usa el mismo servicio para dirección/localidad. La búsqueda
solo completa coordenadas del formulario; el domicilio se conserva.

Tests VPSL: 150 pasaron. Frontend: 16 pasaron, con regresión de habilitación sin
enlace, evento de búsqueda y envío de etiquetas geográficas. TypeScript y build
correctos. Chrome verificó en React que una búsqueda real sin enlace devuelve
200 y completa las coordenadas. Confirmación humana de Jornadas recibida tras probar la búsqueda sin enlace.
