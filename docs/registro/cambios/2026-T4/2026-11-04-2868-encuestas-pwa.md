# Cambio: encuestas configurables en Espacios Comunitarios (#2868)

## Alcance y fuente funcional

Se implementa el alcance del issue: las preguntas se crean en SISOC, cada
encuesta puede habilitarse para PWA y los destinatarios con acceso móvil
pueden responderla. El solicitante confirmó que no debe fijarse el
cuestionario de satisfacción en el código del frontend.

El handoff y las cuatro láminas PDF recibidas se usan como referencia de
diseño: invitación, una pregunta por pantalla, bloques, guardado del avance,
sugerencias, confirmaciones y envío offline. Las 18 preguntas y seis bloques
de satisfacción se cargaron como ejemplo **solo en la base local**, segmentado
a cuentas sintéticas. No hay migración de datos ni cuestionario fijo.

## Dueños y patrón seguido

- SISOC: app existente `src/backends/sisoc_core/encuestas/`; patrón de
  `EncuestaForm`, constructor JSON, versionado y `registrar_respuesta`.
- Acceso móvil: el dueño Comedores resuelve el contrato existente
  `/interno/espacios/contexto/`, como en la API de identidad de Usuarios.
  Encuestas solo consume JSON por `pedir_json_interno`, sin importar el vertical.
  Un contexto no verificable devuelve 503 y no concede acceso.
- Frontend: repositorio `secretarianaf/Espacios-Comunitarios`, rama
  `feat/2868-encuestas-pwa` desde `origin/development` (`20a0002`). Se siguen
  Dexie, la outbox, el motor de sincronización, el layout y Ajustes existentes.
- No se crean apps, servicios, tablas de respuestas ni dependencias. Ninguno
  de los cuatro checklists de alta/movimiento de apps corresponde. Se aplican
  las reglas de aislamiento y fallback del contrato existente.

## Persistencia, permisos y compatibilidad

- Migración `0008_disponibilidad_pwa`: `Encuesta.disponible_pwa=False`,
  `Pregunta.bloque` opcional y `Pregunta.max_caracteres` opcional. Los dos
  últimos permiten representar los bloques y límites del diseño sin fijarlos.
- La opción se conserva al versionar y pasa por la aprobación existente.
  La importación no habilita por sí sola el canal PWA.
- Por indicación del solicitante, el control se ubica en **Segmentación**,
  junto a los destinatarios, y se retira de Crear/editar. Lo guarda el POST
  existente con `change_encuesta`, en la misma transacción que la segmentación.
  Se puede cambiar con una ronda abierta, como los destinatarios. Durante la
  aprobación permanece bloqueado. Un POST anterior sin el control conserva
  el valor y editar el contenido de la encuesta tampoco lo borra.
- API del core: `GET /api/encuestas/pwa/` y
  `POST /api/encuestas/pwa/<ronda_id>/responder/`; registro de URLs regenerado.
  Requiere Token DRF, acceso PWA activo, segmentación y ronda vigente.
- La API no expone puntajes de las opciones ni acepta identidad desde el cliente.
  Conserva anonimato y las tablas existentes de respuestas y cumplimiento.
- El bloqueo de ronda y la unicidad de usuario/ronda hacen idempotente el envío.
  No se vincula UUID o identidad al contenido anónimo. Se conserva el contrato
  actual de rondas recurrentes, en lugar de limitar a una única respuesta histórica.
- Condiciones encadenadas: descendientes de una pregunta oculta tampoco se
  exigen ni guardan. Un test reproduce el caso con operador «distinto de».
- PWA: IndexedDB versión 6 agrega `surveys`, separado por `user_key`; borradores,
  pregunta actual y outbox se conservan entre aperturas. Reintentar no duplica
  pendientes. Una respuesta rechazada puede corregirse sin perder el resto.
- Offline: se retoma solo una sesión org previamente validada, identificada y
  sin cambio de clave pendiente; logout elimina la sesión y no permite retomar.
  Al reconectar se revalida; el servidor vuelve a autorizar cada envío.
- Service worker: app shell para navegación offline y exclusión de la API de
  encuestas del caché HTTP compartido para evitar mezclar usuarios.

## Diseño

Se conserva el azul `#232D4F`, Montserrat, encabezado compacto, opciones
numeradas, selección visible, progreso segmentado proporcional a bloques,
pie Anterior/Siguiente, sugerencias con límite configurable, estados enviando,
error, pendiente y recibido. En tablet se centra a 480 px. La app conserva su
tema claro/oscuro. Los formularios admiten todos los tipos existentes de SISOC.

Guía canónica: `docs/implementaciones/encuestas.md`.

## Deploy y reversa

**Requiere revisión técnica**: migración, registro de URLs, workflow de tests
del editor y autenticación/cache offline del satélite.

Aplicar migración con el migrador completo, actualizar core/worker y después
la PWA. No activar por defecto encuestas previas. El rollback del frontend
mantiene el esquema IndexedDB y borradores; no limpiar almacenamiento ni
eliminar outbox pendiente. La reversa de la migración pierde opción, bloques
y límites nuevos: evaluar esos datos antes de revertirla. Tablas de respuestas
y contenido histórico se conservan.
