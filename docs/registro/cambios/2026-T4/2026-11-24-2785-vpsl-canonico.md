# Ver para Ser Libre: React en las URLs canónicas (#2785)

Con el selector de vertical `vpsl` habilitado, las páginas de itinerarios,
sedes, jornadas y registros sirven la aplicación React existente en las
URLs de Django. No se reemplaza el API ni se redirige a `/v2/`.

## Operación

1. Publicar juntos el backend de VPSL y el build actual de `front_vpsl`.
   Activar la clave `vpsl` en `REACT_VERTICALES_ACTIVAS` sin quitar las
   claves ya activas. En este corte se requiere selección explícita.
2. Ingresar desde el menú de SISOC. Probar enlaces directos y recargas en
   itinerario, jornada, sede, registro, laboratorio y cierre. Verificar
   una baja autorizada y la denegación para otro rol o provincia.
3. Para volver a Django, quitar la clave y reiniciar el runtime de VPSL.
   `/v2/vpsl/` y sus rutas anteriores siguen disponibles.

## Contrato

- Solo se reemplaza el HTML de GET/HEAD en las rutas declaradas en
  `src/backends/vpsl/ver_para_ser_libre/urls.py`. El callback nativo
  decide permisos, alcance, redirecciones y estado antes de pedir el
  shell fijo a `front_vpsl`. Los parámetros de la URL no se reenvían al
  estático y el HTML canónico se devuelve como privado y no almacenable.
  Si el upstream no responde con HTML válido y el marcador de versión
  de rutas canónicas, permanece Django. HEAD comprueba el mismo build
  y conserva las cabeceras sin devolver el cuerpo.
- Las acciones React consumen las mismas APIs de VPSL. Los métodos de
  escritura nativos, exportaciones, búsquedas auxiliares y adjuntos
  continúan por sus rutas existentes. El preview de baja incluye el
  retorno al listado o actividad padre ya usados por Django.
- El detalle de sede no tenía ruta Django separada. React lo muestra
  desde `/ver-para-ser-libre/sedes/?sede=<id>`, en lugar de agregar una
  ruta que coincida con utilidades de sede o hacer un salto a `/v2/`.

## Verificación y límites

Los listados canónicos de itinerarios y sedes con parámetros preexistentes
(incluidos `busqueda`, `buscar_por`, `estado`, `provincia`, `localidad`,
fechas, `filters` y `page`) siguen en Django para respetar los enlaces
guardados. La única excepción es la consulta nueva `?sede=<id>`. El
cierre de VPSL requiere incorporar la interfaz de filtros avanzados y
volver a probar los enlaces guardados antes de retirar ese retorno.

Se observaron primero los fallos de entrada canónica, navegación y baja
en Vitest y de montaje HTTP en pytest. Las pruebas de ruta y API usan
datos sintéticos; la prueba del proxy reemplaza el estático por una
respuesta controlada. No prueban el build publicado ni el recorrido real
de escritorio/móvil/teclado; registrar esa evidencia antes de activar
VPSL en un entorno. El build anterior queda en Django aunque el servicio
estático esté disponible.

## Activación y rollback

`canonical_entry.react_enabled()` sigue la semántica de `core.react_activation`:
VPSL se activa con `todas` (el valor por defecto sin `REACT_VERTICALES_ACTIVAS`)
o con la clave `vpsl`; `ninguna`, una variable vacía o una lista sin `vpsl`
dejan Django. Con la vertical apagada, Sedes e Itinerarios devuelven la
respuesta nativa sin cambios: no sirven JSON ni agregan `Cache-Control` o
`Vary: Accept`. Rollback sin desplegar código: definir la variable sin `vpsl`.
