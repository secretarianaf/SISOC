# 2026-11-06 - Protocolo G1 v1 para APIs web remotas de verticales (#2808)

## Estado

Aprobada por el responsable el 2026-11-06, con un cambio sobre la propuesta:

> "apruebo la opcion A pero cambia los 25 segundos por 60 segundos, ya que debemos prepararnos para equipos lentos"

Integrada en el mismo trabajo como mecanismo común, sin APIs reales de verticales
(ver [el cambio](../cambios/2026-T4/2026-11-06-2808-gate-g1-v1.md)). La ventana de
60 s y la decisión de igualarla al read timeout solo para `/api/web/<vertical>/`
las propuso el agente para cumplir el pedido sin cambiar los timeouts de las rutas
existentes.

## Contexto

Las pantallas React de los verticales necesitan APIs web en el runtime de cada
vertical. El core es dueño de la sesión y de los requisitos web: acceso web,
contraseña, perfil y encuesta. Hoy reenvía a cada vertical con
`src/backends/kernel/core/backend_proxy.py`.

Los experimentos G1-E01 a E07 se corrieron el 2026-11-06 en un entorno sintético y
aislado: core y runtime PAS con gunicorn en contenedores separados, red interna,
SQLite compartida e imagen fijada (Django 5.2.17, requests 2.34.2, gunicorn 23.0.0),
con un prototipo descartable fuera del repositorio. Resumen:

- E01: en los casos reenviados, el `path_url` firmado coincide byte a byte con
  `RAW_URI` en el runtime (`%2F`, `%25`, `%7e`, `+`, `%20`, Unicode, duplicados,
  vacíos, `?` final, `%3F`, `%23`, `;`). Un header del cliente no lo reemplaza.
- E02: sin G1, los requests que el core cerró con 504 igual ejecutaron negocio
  después. Con `max_age` igual al read timeout se rechazan los que empiezan tarde.
- E03: el header ocupa unos 1,33 × target + 260 bytes. Un target de 4000 bytes
  entra en los límites de gunicorn.
- E04: bajo `/<vertical>/api/web/`, los middlewares de redirección del core
  contestan 302 HTML; bajo `/api/` quedan exentos.
- E05: Django hace `cycle_key()` cuando el hash de sesión solo valida con un
  `SECRET_KEY_FALLBACKS`; el binding debe usar la clave de la cookie entrante.
- E06: las alteraciones de campos, firma y headers se rechazan sin ejecutar negocio.
  Una constancia válida se puede repetir dentro de la ventana.
- E07: las rutas existentes no cambian con G1 activo.

## Decision

**Opción A: G1 v1 con la clave compartida existente (`SECRET_KEY`).**

- Namespace: `/api/web/<vertical>/`. Un vertical lo publica agregando ese prefijo,
  con su propio nombre, a `url_prefixes` en `src/backends/config/backends.json`. El
  proxy rechaza al arrancar (`ImproperlyConfigured`) un `api/web/<otro>/`.
- El core exige sesión y evalúa `SISOC_WEB_ACCESS_POLICY`
  (`usuarios.web_session.resolve_web_access`). Sin sesión responde 401 JSON y con
  un requisito pendiente 403 JSON con `state` y `required_action_url`, sin reenviar.
- El core elimina siempre `X-SISOC-Web-Gate` del cliente, firma el `path_url` del
  único `PreparedRequest` que envía y sanea o genera `X-Request-Id` (sin firmarlo).
- Constancia: header interno `X-SISOC-Web-Gate`, `TimestampSigner` (SHA-256) con
  salt `sisoc.web-gate.v1`. Campos exactos: `v`, `aud`, `sub`, `session_binding`,
  `method`, `target` e `iat`. El binding es `salted_hmac` con salt
  `sisoc.web-gate.session.v1` sobre la clave de sesión de la cookie entrante.
- El runtime verifica en `core.web_gate.WebGateMiddleware`, después de
  `AuthenticationMiddleware` y antes de que una vista o CSRF lean el cuerpo:
  - header de 6144 bytes como máximo;
  - `iat` no más de 2 s en el futuro ni más antiguo que **60 s**;
  - `aud` igual a `SISOC_BACKEND`, `sub` igual al usuario, `method` igual al
    método recibido y `target` igual a `RAW_URI` de gunicorn (sin `RAW_URI`, 503);
  - firma y binding con `SECRET_KEY` y `SECRET_KEY_FALLBACKS`.

  Después aplican la autenticación de sesión, CSRF, permisos y objetos del dueño.
- Target de más de 4000 bytes: 414 JSON en el core, sin reenviar.
- Read timeout del proxy: 60 s solo para `/api/web/<vertical>/`, igual a la
  ventana. Las rutas proxied existentes conservan 5 s de conexión y 25 s de lectura.
- Errores JSON: runtime caído antes del envío, 503. Timeout o pérdida después del
  envío: 504; en métodos no seguros con `uncertain: true`. Nunca hay reintento
  automático. Todas las respuestas llevan `Cache-Control: private, no-store` y
  `Vary: Cookie`.
- Monolito (`config.settings_all`): `WebGatePermission` evalúa la política local y
  nunca confía en el header, que el middleware descarta.

**Alternativa B (descartada):** el mismo formato con un secreto dedicado. Desacopla
su rotación de la de sesiones a cambio de distribuir un secreto nuevo y no agrega
aislamiento frente a un runtime que ya tiene `SECRET_KEY`.

## Consecuencias

- Las familias bloqueadas solo por G1 pueden avanzar sobre este mecanismo. Cada API
  real de vertical es un trabajo aparte que agrega su prefijo y sus vistas con
  `WebGatePermission`.
- Condición previa resuelta en el mismo cambio: si la autenticación del core rota la
  clave de sesión dentro de un request proxied, el proxy reenvía la clave vigente y
  emite su `Set-Cookie`. Antes reenviaba la clave vieja y el cliente perdía la sesión.
- Rotación de clave en este orden: fallback en todos → runtimes → core → retiro del
  fallback. Envolvente y binding usan la misma lista de claves.
- **Límite de los 60 s:** gunicorn corre con su timeout por defecto de 30 s en el core
  y en los runtimes (`docker/django/entrypoint.py`,
  `docker/compose/docker-compose.deploy.yml`). Con esa configuración, un request de
  más de 30 s termina con el worker abortado (500 HTML observado en el entorno
  sintético) antes del 504 JSON. Para que la ventana de 60 s sirva a equipos lentos
  hay que subir `--timeout` de gunicorn (core por encima de 60 s, runtimes al menos
  60 s). Eso afecta a todas las rutas del proceso y queda como decisión pendiente.
- Riesgo residual:
  - no hay anti-replay dentro de la ventana de 60 s;
  - la fuente cruda del target depende de gunicorn (`RAW_URI`);
  - el proxy reescribe `%2F` a `/`: las APIs web no deben darle significado a `%2F`;
  - el desvío de reloj se midió en un solo host;
  - PWA, el resto de los verticales, Nginx y carga realista no se probaron.
